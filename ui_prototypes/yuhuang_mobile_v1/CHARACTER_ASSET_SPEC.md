# 原创角色主视觉素材规范

## 1. 文档目的

本文件用于指导后续原创生成角色素材，确保首批 8 个传统文化角色在手机端首页中具有统一画风、统一构图、统一光影和统一安全区，能够稳定接入现有 UI，并适合老人观看和使用。

本规范不授权复制影视画面或具体演员形象。本轮只建立规范，不生成、不下载、不接入真实图片或视频。

## 2. 当前适配页面

- 页面类型：手机竖屏 Web 首页；
- 主要验收尺寸：390×844；
- 兼容尺寸：360×800、430×932；
- 当前 UI 覆盖内容：顶部角色切换、顶部余时和充值、左右三个辅助入口、底部状态字幕带、开始叙话按钮、费用提示；
- 设计目标：主视觉优先，角色清晰，控件可读且不遮挡人物关键部位。

## 3. 首批角色和统一画风

首批至少包括：

| 角色 | 目录标识 |
| --- | --- |
| 玉皇大帝 | `yuhuang` |
| 孙悟空 | `sunwukong` |
| 观音菩萨 | `guanyin` |
| 太上老君 | `taishanglaojun` |
| 财神爷 | `caishen` |
| 猪八戒 | `zhubajie` |
| 唐僧 | `tangseng` |
| 沙悟净 | `shawujing` |

所有角色统一采用“中式古典、东方神话、写实插画”的视觉语言：人物造型可信、材质细腻、场景具有绘景感，但不追求影视剧照或具体演员般的照片复刻。

禁止混搭：

- 有的角色照片写实、有的角色二次元；
- 有的角色国漫夸张、有的角色影视剧截图；
- 有的角色高饱和网游风、有的角色低饱和古典风；
- 同一批头像使用不同头身比例、光线方向或背景复杂度。

## 4. 通用主视觉素材规范

### 4.1 基础规格

| 项目 | 统一要求 |
| --- | --- |
| 素材类型 | 手机首页角色与场景一体化主视觉 |
| 推荐比例 | 9:16 |
| 最低尺寸 | 1080×1920 |
| 优先尺寸 | 1440×2560 |
| 静态格式 | WebP，正式上线必需，用作 poster 和静态兜底 |
| 动态格式 | WebM，正式上线必需，用作首页默认动态主视觉 |
| 色彩 | sRGB，低饱和、层次清楚，避免刺眼高亮 |
| 构图 | 正面或轻微正侧的完整人物，背景与角色统一绘制 |

### 4.2 画面要求

- 角色与背景必须一体化，不能是孤立人物抠图；
- 不得带棋盘格背景、假透明底、白边或抠图毛边；
- 不得带水印、字幕、边框、按钮、价格、平台标识或其他 UI；
- 人物不能因竖屏裁切而变形、拉长或压扁；
- 角色主体不能缩得过小，老人需要在手机上清楚识别脸部、服饰和姿态；
- 场景要有前、中、远景层次，但不能用复杂细节干扰控件文字；
- 光影统一采用柔和暖光与克制高光，脸部保持明亮、自然、可亲近；
- 不使用恐怖、阴森、强压迫、强战斗或网游充值页式视觉。

### 4.3 开发验证与正式上线

开发验证阶段允许先制作 `scene.webp`，用于确认人物造型、构图安全区、场景色彩和控件遮挡关系，页面也可以暂时只显示静态开发预览。

正式角色上线阶段，`scene.webp` 与 `scene.webm` 必须成对完成。只有静态图、没有动态场景的角色，不算完成正式主视觉验收，可以继续标记为静态开发预览或“尚待迎请”。制作时先验证静态构图，不代表正式页面运行时优先使用静态图。

## 5. 通用构图安全区

安全区用于给页面控件留出可读空间，不代表必须画成空白色块。可使用天空、霞光、远景云雾或低细节宫阙自然过渡。

### 5.1 顶部安全区

- 顶部约 14%～18% 的高度避免放置人物脸部、眼睛、冠冕主体和其他关键细节；
- 以 1440×2560 素材为例，顶部约 360～460px 应保持低细节；
- 冠冕不能顶到画面最上边，顶部必须留出呼吸空间；
- 角色脸部建议落在画面中上部偏中央，且低于顶部角色切换和余时入口；
- 顶部可以使用深酒红天幕、柔和霞光或低对比远景，不使用大面积纯黑蒙层。

### 5.2 左右中部安全区

- 左右中部各约 18% 的画面宽度避免放置关键手势、脸部、冠饰和主要法器；
- 以 1440px 宽素材为例，左右各约 260px 以低细节背景为主；
- 角色肩部可以进入边缘区域，但不能让侧边入口正好盖住肩部轮廓和识别性装饰；
- 双手尽量靠近身体中轴或位于侧边入口之间的安全中心区；
- 左右边缘允许轻微暗角，但人物身体中央不得被暗色蒙层覆盖。

### 5.3 底部安全区

- 底部约 20%～24% 的区域以云海、云台、低细节衣摆或柔和地面为主；
- 以 2560px 高素材为例，底部约 510～615px 为状态字幕、主通话按钮和费用提示预留；
- 双手和重要服饰纹样不要落在状态字幕带正后方；
- 人物脚部可以自然融入云海，但不能出现被生硬截断的腿部或衣摆；
- 底部云台应能与深玉绿色麦克风按钮自然衔接。

### 5.4 中央角色区域

- 人物冠冕、脸部、胸肩和主要手势集中在画面中央约 46%～58% 的宽度内；
- 脸部清晰度必须足以在 390px 宽手机上识别神态；
- 不通过把人物缩得很小来规避 UI 遮挡；
- 同一批角色保持接近的脸部尺寸和眼位高度，切换角色时不应产生主体忽大忽小的跳变。

## 6. 头像和角色卡规格

### 6.1 `avatar.webp`

- 比例：1:1；
- 推荐尺寸：512×512，最低不低于 384×384；
- 构图：头肩像，脸部居中略偏上，头顶保留约 8%～12% 安全边距；
- 视线：平视或轻微正侧，表情与首页主视觉一致；
- 背景：使用对应场景的低细节延续色，不使用纯白抠图底；
- 裁切：同时适合圆形和圆角方形裁切，关键冠饰与脸部不得超出中央 80% 安全区；
- 一致性：8 个角色使用相同脸部尺度、光线方向、景别、清晰度和背景复杂度；
- 禁止文字、角色名、水印、边框和状态标签直接写入图片。

### 6.2 `card.webp`

- 可选素材，推荐比例 4:5，推荐尺寸 960×1200；
- 用于角色介绍或角色选择卡封面，不替代 `avatar.webp`；
- 延续同一角色的服装、脸部、背景和光影设定；
- 四周保留约 8% 安全边距，不在图内添加 UI、价格或宣传文案。

## 7. 八个角色的气质约束

### 7.1 玉皇大帝 `yuhuang`

关键词：庄重、慈祥、沉稳、可信赖、仙风道骨、天庭至尊但不压迫、适合老年陪伴、熟悉的中式神话审美。

年代感和气质可以抽象参考 86 版《西游记》的中式神话舞台美术氛围，但不得复制任何具体影视画面、镜头、服装细节或演员形象。

服饰方向：

- 天庭帝王袍服；
- 暖金、玉白、低饱和朱红；
- 冠冕清楚但不顶边；
- 衣袍具有自然垂坠感；
- 不使用夸张战斗盔甲或网游装备。

神态方向：

- 平和、慈祥、略带威严；
- 目光稳定，不凶、不怒；
- 不使用商业广告式微笑或动漫夸张表情。

背景方向：

- 赤霄天庭、远处宫阙、天门、暖金天光、多层云海、玉白云台；
- 红而不俗，不做婚庆红，不做网游充值页红；
- 宫阙用于营造空间，不抢人物主体。

动作方向：

- 正面或轻微正侧的全身站姿；
- 手势自然稳重，不大幅挥手；
- 不做战斗动作，不持夸张法器。

动态方向：

- 云海缓慢流动；
- 暖金天光轻微变化；
- 袍摆或冕旒极轻微移动；
- 人物身体保持稳定。

### 7.2 孙悟空 `sunwukong`

- 活泼、机敏、直爽，但不能喧闹、凶狠或持续战斗化；
- 保留陪伴老人说笑解闷的亲近感；
- 动作可以比其他角色轻快，但仍应站稳、面向用户；
- 金箍棒如出现，应作为克制的身份标识，不横跨安全区或形成攻击姿态；
- 不使用夸张网游铠甲、火焰爆炸或动漫兽化表情。

动态方向：

- 云气可以略比其他角色活泼，但仍保持低速；
- 披风或束带轻动；
- 不得挥舞金箍棒；
- 不得做战斗循环。

### 7.3 观音菩萨 `guanyin`

- 温柔、平和、清净、柔和，具有安静倾听感；
- 神态慈悲但不过度神化发光，不形成刺眼强光；
- 服饰以玉白、柔和浅金和低饱和自然色为主；
- 手势简洁安定，不让净瓶、柳枝或手部落在侧边和底部控件后方；
- 避免照片式宗教塑像感，也避免二次元少女化。

动态方向：

- 莲台柔光轻微变化；
- 水雾或云雾缓慢移动；
- 披帛轻微飘动；
- 人物和手势保持平稳。

### 7.4 太上老君 `taishanglaojun`

- 沉稳、睿智、从容，突出仙家长者气质；
- 面容年长但精神温和，不塑造成阴沉、衰弱或高高在上的审判者；
- 道袍、发冠和拂尘保持克制，不用繁复法术特效；
- 场景可使用丹房、云台或仙山远景，但必须与整套东方神话绘景质感统一；
- 适合陪老人聊传统文化和人生经验。

动态方向：

- 炉烟、丹气或远处仙雾缓慢升腾；
- 拂尘只能极轻微移动；
- 人物姿态保持稳定；
- 不得出现法术爆闪。

### 7.5 财神爷 `caishen`

- 喜庆但不能俗艳，亲切富态，避免金钱崇拜和网游财神形象；
- 以温暖、吉祥、可信赖为主；
- 红金配色必须低饱和、有材质层次，不使用满屏金元宝、金币雨或充值特效；
- 神态开朗稳重，不使用推销式笑容；
- 重点表达祝福、安康和好日子，而不是炫耀财富。

动态方向：

- 瑞气、祥云和衣袍轻动；
- 不得出现金币雨；
- 不得让元宝旋转；
- 不得出现充值特效。

### 7.6 猪八戒 `zhubajie`

- 憨厚幽默、亲切接地气，但不能丑化、低俗化或只突出贪吃；
- 要有陪老人说笑解闷的气质；
- 保留角色识别特征，同时控制夸张鼻相、体态和滑稽表情；
- 动作自然放松，不拿食物作为唯一视觉中心；
- 服装和背景继续遵守整套古典神话写实插画风格。

动态方向：

- 背景云雾和衣摆轻动；
- 不得表现夸张肚皮呼吸；
- 不得循环吃东西；
- 不得持续做滑稽表情。

### 7.7 唐僧 `tangseng`

- 温和克制、端庄慈悲，避免说教感过强；
- 适合安静倾听和文化陪伴；
- 神态沉静但不疏离，目光柔和、有耐心；
- 袈裟与法器保持庄重克制，不使用强烈宗教光环压过人物；
- 姿态以安定站立或自然合手为主，避免持续讲经式手势。

动态方向：

- 袈裟边缘和环境柔光轻动；
- 人物姿态保持安定；
- 不得循环念经；
- 不得出现嘴部循环运动。

### 7.8 沙悟净 `shawujing`

- 沉稳可靠、朴实忠厚，避免沉闷和边缘化；
- 突出踏实陪伴感；
- 体态坚实但不形成武力压迫，神态诚恳、安定；
- 降妖宝杖如出现，应垂直或自然收束，不横挡身体和 UI；
- 场景与光影要给予其和其他首批角色同等的主体地位和精细度。

动态方向：

- 厚重云气、衣摆和远景光线轻动；
- 兵器保持稳定；
- 人物身体保持稳定；
- 不得做战斗动作。

## 8. 正式动态主视觉规范

正式产品首页默认展示 `scene.webm`。首批 8 个角色正式上线时，`scene.webm` 与 `scene.webp` 均为必需素材；动态场景必须建立在已经验收的静态构图基线上。

页面运行时展示优先级为：

```text
scene.webm → scene.webp → 页面 CSS 降级背景
```

### 8.1 WebM 统一规格

| 项目 | 统一要求 |
| --- | --- |
| 格式 | WebM |
| 比例 | 9:16 |
| 画面尺寸 | 与同角色 `scene.webp` 保持相同比例和构图基线 |
| 建议循环时长 | 8～12 秒 |
| 节奏 | 低速、低幅度、无突然变化 |
| 音频 | `scene.webm` 文件本身不得包含任何音频轨道；网页接入时仍必须设置 `muted` |
| 播放 | 自动播放、静音、循环、手机内联播放，不得自动全屏 |
| 循环 | 首末帧连续，人物位置和亮度不跳变，云雾方向自然闭合 |

循环末尾不得出现明显回弹。人物主体必须稳定，不能为了“看起来在动”而让角色像纸片人在水里漂。

### 8.2 移动 Web 性能目标

- 在不明显降低画质的前提下尽量控制文件体积；
- 单角色 `scene.webm` 建议目标不高于 5MB；
- 超过 8MB 时必须重新评估编码、时长、分辨率和动态复杂度；
- 以上体积是项目建议目标，不是固定平台限制。

### 8.3 允许出现的动态

- 云海缓慢横向或纵深流动；
- 霞光轻微明暗变化；
- 柔和光晕呼吸；
- 远处宫阙轻微空气透视变化；
- 衣角、袍摆、披帛极轻微摆动；
- 香烟、炉烟、水雾等角色专属环境动态；
- 极少量低速光点。

### 8.4 禁止出现的动态

- 嘴型无意义循环；
- 高频眨眼；
- 反复摇头；
- 身体左右摇摆；
- 胸口夸张呼吸；
- 人物整体上下漂浮；
- 镜头推进和拉远；
- 画面整体缩放；
- 高速云雾穿过脸部；
- 爆闪；
- 金币雨；
- 火焰爆炸；
- 粒子喷发；
- 按钮和字幕随背景移动；
- 自动播放声音。

## 9. 静态兜底规范

`scene.webp` 是正式上线必需文件，承担：

- 视频 poster；
- 视频加载前显示；
- 视频加载失败；
- 系统减少动态效果；
- 用户手动选择静态模式；
- 弱网或省流量模式；
- 不支持动态播放的设备。

同一角色的 `scene.webp` 与 `scene.webm` 必须保持：

- 同一人物；
- 同一服饰；
- 同一场景；
- 同一构图；
- 同一眼位；
- 接近的亮度和色彩。

不能让动态视频使用一套形象，静态兜底图又出现另一套脸、服饰或场景。

## 10. 文件命名最终规范

每个首批角色目录未来统一使用：

| 文件名 | 正式上线是否必需 | 用途 |
| --- | --- | --- |
| `scene.webm` | 是 | 首页默认动态主视觉 |
| `scene.webp` | 是 | poster 和所有静态兜底场景 |
| `avatar.webp` | 是 | 角色选择头像 |
| `card.webp` | 否 | 角色介绍卡片 |
| `notes.md` | 建议 | 记录版本、来源、生成提示词和权利信息 |

不得加入角色名、版本号、中文或临时描述到正式文件名中。生成过程中的候选稿应放在工程外部评审，不在正式目录中堆放 `final2`、`new`、`test` 等文件。

8 个角色的最终目录对应关系：

```text
assets/characters/yuhuang/
assets/characters/sunwukong/
assets/characters/guanyin/
assets/characters/taishanglaojun/
assets/characters/caishen/
assets/characters/zhubajie/
assets/characters/tangseng/
assets/characters/shawujing/
```

## 11. 后续网页接入规范

未来页面可以参考以下结构，本轮不修改当前 HTML：

```html
<video
  autoplay
  muted
  loop
  playsinline
  poster="./assets/characters/yuhuang/scene.webp">
  <source
    src="./assets/characters/yuhuang/scene.webm"
    type="video/webm">
</video>
```

后续接入必须满足：

- 视频位于所有 UI 控件后方；
- 视频设置 `pointer-events: none`；
- 加载失败后显示 `scene.webp`；
- 不加入播放器控制栏；
- 不自动播放声音；
- 角色切换时同时切换 `scene.webm` 和 `scene.webp`；
- 减少动态模式隐藏 `scene.webm` 并显示 `scene.webp`。

## 12. 产品默认与用户选择

- 正常默认模式：播放低速动态主视觉 `scene.webm`；
- 减少动态模式：显示静态 `scene.webp`；
- 弱网、省流量或动态播放失败：显示静态 `scene.webp`；
- 最终静态素材也无法显示：使用页面 CSS 降级背景。

未来可以增加“动态场景 / 静态场景”的用户主动选择，但当前原型阶段不增加设置按钮或 JavaScript。
